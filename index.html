A small, stable API in front of ICE Encompass.

An open-source, stateless middleware template for field-filtered reads, asynchronous FIFO writes, role-scoped vendor onboarding, field schema discovery, eFolder document upload and download, and enhanced conditions. It deploys into the lender's AWS account and keeps no loan database or mirror.

What it does

Field-filtered reads

GET /v1/loans/{id}?fields=11,12,1109 returns only the requested fields, with a 30-second per-container cache scoped by persona.

Async FIFO writes

PATCH /v1/loans/{id} validates and enqueues a job, returns 202, and retries Encompass file locks through SQS.

Request-ID tracing

Every response returns x-request-id. Write jobs, SQS messages, worker logs, and metadata-only API Gateway access logs carry the same ID, with Lambda error and API 5xx alarms.

Role-scoped onboarding

Title, broker, and appraisal invite links provision API keys locked to a server-side Encompass service-account persona. No admin token.

Field schema discovery

GET /v1/fields?ids=11,646,CX.TITLE.STATUS resolves standard and CX.* custom fields from Encompass's native schema APIs and reports readOnly/fieldLock when supplied.

Documents & conditions

GET /v1/loans/{id}/documents, POST /v1/loans/{id}/attachmentUploadUrl, POST /v1/loans/{id}/attachmentDownloadUrl, and GET/PATCH /v1/loans/{id}/conditions cover eFolder documents and enhanced conditions. File bytes go straight to and from Encompass.

Deploy in one line

Run inside AWS CloudShell. The template is larger than CloudFormation's 51,200-byte direct-upload limit, so the installer creates an S3 bucket and hosts it there automatically. To use the console, upload template.yaml to S3 first. The installer asks for the Encompass instance ID, API client ID, and client secret, then prints the gateway URL and three role-scoped invite links.

bash <(curl -sSL https://raw.githubusercontent.com/Spuds0588/Encompass-API-Passhrough-Middleware-Gateway-/main/deploy.sh)

Full parameter reference, smoke tests, and local development instructions are in the README.

Field discovery

The lender's custom fields are invisible to public ICE documentation. The gateway queries the lender's own Encompass schema on demand and returns the authoritative definitions.

curl -s "$GATEWAY_URL/v1/fields?ids=11,646,CX.TITLE.STATUS" \
  -H "x-api-key: $KEY"

Common questions

What is the Encompass API Passthrough Gateway?

It is a stateless AWS middleware template that gives vendors a small, stable API for field-filtered ICE Encompass reads, asynchronous writes, role-scoped API key onboarding, and field schema discovery. It keeps no loan database or mirror; write payloads transit SQS and read projections stay in Lambda memory for up to 30 seconds.

Is this project affiliated with ICE Mortgage Technology?

No. This is an independent, community-supported open-source template. It is not affiliated with or endorsed by ICE Mortgage Technology. Encompass is a trademark of its respective owner.

Does the gateway store loan data?

It keeps no loan database or mirror. It reads from Encompass on demand and proxies writes. Tenant mappings, short-lived OAuth tokens, and job metadata are stored in DynamoDB; write payloads transit an encrypted SQS FIFO queue for up to 1 day (DLQ 4 days); read projections stay in Lambda memory for up to 30 seconds. Document lists and conditions are passed through without storage; uploaded and downloaded file bytes go directly to and from Encompass's pre-signed URLs.

Has this been tested against a live Encompass instance?

The maintainers do not have access to a live Encompass developer instance or a lender AWS account. CI and local fakes verify routing, auth, caching, retries, and template integrity. Real-instance validation is a shared community responsibility and should be performed in each deployment environment.

How do I report a bug or contribute a fix?

Open a GitHub issue with a minimal reproduction, sanitized evidence such as redacted field shapes and deployment or log excerpts, and the commit you tested. Submit fixes as pull requests with a regression test and updated docs. Never include client secrets, API keys, invite codes, loan data, or PII.

What Encompass roles are supported?

The template supports title and settlement, TPO and broker, and AMC and appraisal roles. Each role is mapped server-side to its own Encompass service-account persona.

Can a broker read documents and respond to conditions?

Yes. The gateway lists eFolder documents, initiates Encompass's pre-signed attachment upload, returns pre-signed download URLs, and reads or responds to enhanced conditions. File bytes move directly between the vendor and Encompass storage; the gateway never proxies or stores them.
